# Общая координация разработки

Канонический журнал: `/opt/zinaida/coordination/registry.json` на основном сервере.
Чтение перед выбором работы, правкой общих файлов и развёртыванием:

```bash
python3 /opt/zinaida/coordination/code/work_registry.py read --root /opt/zinaida/coordination
```

В журнале есть ветка, ответственный поток, занятые пути, доказательства,
точка продолжения, следующий шаг и срок актуальности записи. `observed` означает
наблюдение по документам другого чата, а не подтверждение участия этого чата.
`working` означает работу текущего хода, `paused` сохраняет резерв без обещания
фонового исполнения. После истечения срока запись требует сверки; её пути
не освобождаются автоматически. `released` разрешён после выяснения исхода работ.

Изменение: `update --root ...`, один JSON на stdin с `expected_revision` и
`record`. Схему record смотреть в work_registry.py. Все изменения сериализуются
OS-lock, записываются атомарно и проверяют версию. Пересечения путей, включая
вложенные каталоги, запрещены между потоками. Это кооперативный механизм,
не граница безопасности: root может обойти его. Запрет автоматически не
распространяется на инструменты другого чата, который ещё не прочёл правила.

Разделение текущих работ:

| Поток | Область |
| --- | --- |
| Видеомонтажер3 / PR2 | GPU, аренда, сцены, монтажный ZIP, CPU-правки |
| Видеоинтеграция / PR3 | pult_link, pult_export, integrations, coordination |
| Мегамозг | Общая служба, авторизация, admission-манифесты и развёртывание |

Общие Library-документы обновлять с expected_current_version, сохраняя чужие
свежие разделы. Общую базу и службу не заменять копией стенда. Перед изменением
рабочей установки зарегистрировать общий ресурс и сверить незавершённые операции.
Запись следующего шага не запускает исполнителя. Секреты и полные переписки
в журнал не помещать. При переходе в новый чат передать ID той же записи,
прочитать свежую ревизию и обновить её, а не создавать конкурирующего владельца.
