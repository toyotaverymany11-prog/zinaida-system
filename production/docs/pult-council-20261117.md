## Принято

Один общий пульт Мегамозга и раздел видеопроизводства внутри него. Общий пульт
ведёт поручения, личность и назначения. Видеопроизводство ведёт исходники,
планы сцен, версии, попытки и приёмку точного медиа. Не создавать вторую общую
очередь. Модель принимает творческие решения через разрешённый маршрут;
Hermes не объявляется обязательным посредником каждого запроса.

Первый шаг: привязка task/revision/owner к order/fingerprint, только чтение в
существующей карточке. Второй: защищённое видео и замечания к версии. Третий:
CPU-путь от поручения до одной правки и человеческой приёмки. Отдельный шаг:
проверка видео через фактическую подписку Grok. Снимок SuperGrok Heavy/1% и
OAuthCLI не подтверждает этот способ генерации; API не подставлять автоматически.
Сначала качество и рабочий цикл, затем измеренная оптимизация принятого результата.

Разделение работ: аренда/GPU/скорость загрузки остаются в третьем чате и PR2.
Этот поток добавляет интеграцию в отдельной ветке без изменения его файлов.
Новые платные операции текущим этапом не запускались. Разрешённый ранее бюджет
GPU-разработки не отменён и не заменён нулём для другого потока.

## Рецензия реализации и исправления

1. Сравнение отзыва с сохранённым планом не доказывает актуальность исходников.
   Исправлено: статус recorded_acceptance_unverified, evidence_current=false;
   изменённый evidence проверяется тестом. Приёмка фильма всегда false.
2. HTTP-таймаут не останавливает поток файлового чтения. Исправлено: один
   незавершённый read на весь adapter; слот не освобождается после timeout.
   Параллельные и повторные GET не создают новые потоки; 12 одновременных
   запросов проверены. Полное принудительное завершение зависшего OS I/O не
   заявляется; для установки нужен ограниченный доверенный exporter.

## Результат и ограничения

12 unit и26 реальных isolated HTTPS/browser проверок прошли. На копии текущего
пульта карточка показывает этап заказа, reload и ширину390/1024. Неавторизованный,
сотрудник и другой владелец не читают источник; отзыв сессии во время чтения
проверен. Исходная DB не изменилась, модельных задач и исполнения0.
Визуально просмотрен мобильный блок. Общие22 исходных файла пульта не изменены.

Это технически проверенный первый adapter, не установка в публичный пульт,
не выдача MP4, не допуск сотрудников и не сквозное художественное производство.
Не ставить отметку «готово» всему business-pilot. Пересмотреть выбор общей
оболочки, если защищённое видео и права потребуют крупной переделки пульта.
Следующий шаг: явная production binding и bounded exporter, затем защищённый
доступ к точной версии видео. Никаких новых фоновых исполнителей не оставлено.

## Продолжение разработки после первого этапа

Дорожные карты согласованы: живой план Мегамозга72→73, Library architecture25
и handoff20 сохранили свежие20.32/20.33 соседнего потока. Теперь GPU-сцена и
переносимый ZIP технически проверены там; остановка20.31 не текущий блокер.

Добавлен production.pult_export: один отдельный процесс с deadline, один lock,
атомарный JSON до4096байт, только разрешённые поля. Пульт читает JSON без доступа
к исходной SQLite; исходное время не обновляется чтением. Истёкшие данные
не являются свежим состоянием. При неудачной атомарной записи старый снимок
остаётся до истечения его срока. Расписания и публичной установки пока нет.

Повторная рецензия Terra не выявила блокера отдельного стенда; reviewer тесты
сама не запускала. Реальная проверка от Unix-пользователя megamozg-pult затем
выявила потерю группового чтения при umask077. Исправлено fchmod0640 только
публикуемой metadata; setgid каталога определяет группу. Регрессионный тест
добавлен. Worker использует тот же пакет через изолированный Python -I,
не зависит от текущей папки и PYTHONPATH вызывающего процесса.

Теперь21 unit (12+9) локально и на сервере,28 HTTPS/browser проверок. В браузерном
прогоне источник после экспорта убран с прежнего пути, карточка/reload продолжают
работать только по JSON. Реальный заказ41981498-9965-4fd7-a873-f78f5695c0a8
экспортирован в изолированный временный каталог с синтетической привязкой задачи.
Настоящий Unix-пользователь пульта прочитал JSON, но не имеет права читать
исходную DB; её SHA не изменился. Общие22 файла пульта также неизменны.
На Python3.13 серверные тесты сообщают ResourceWarning о незакрытых SQLite
соединениях существующей тестовой/Intake-обвязки. Новая read-only коллекция
использует closing; исправления чужого Intake в эту ветку не вносились.

Это не рабочая публичная карточка реального заказа и не доступ сотрудника.
Осталось проверить производственную привязку, ограниченное обновление снимков,
общий допуск установки и публичный путь; затем защищённые MP4/ZIP и правки.
